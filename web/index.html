Pricing regression review

Check a pricing change before you trust it

Pick a prepared change, let Muse propose verification cases, confirm the expected totals against the written rule, then compare the original and candidate implementations and export a runnable regression test.

NO SESSION

  1. Select a change

    Read the rule and the proposed diff before going further.

  2. Ask Muse for verification cases

    Muse proposes up to three cases with expected totals. Nothing is executed at this step.

  3. Validate the expectations

    Check every expected total against the rule yourself. Edit any value that is wrong, then confirm you reviewed them. Edited values are recorded as reviewer corrections, not as Muse discoveries.

  4. Compare original and candidate

    The backend runs both implementations against the accepted cases. Expectations are locked first.

  5. Export a regression test

    The accepted cases become a runnable test so this check can be repeated.

This reviewer shows what the backend reports for the selected cases only. A green comparison is evidence for those cases, not proof the change is correct for every basket, and it does not approve any merge or deployment.
